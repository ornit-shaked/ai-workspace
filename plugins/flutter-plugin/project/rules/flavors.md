# Rule: Flavors — Development / Staging / Production

**Scope:** entire project

This project always runs through one of three explicit environments, never a single undifferentiated
build:

- `lib/main_development.dart`
- `lib/main_staging.dart`
- `lib/main_production.dart`

`lib/main.dart` only delegates to `main_production.dart` — it holds no logic of its own. Each
entry point sets `AppConfig.flavor` (see `lib/config/app_config.dart`) before running the app, so
environment-dependent code (API base URLs, feature flags, logging verbosity) reads from
`AppConfig` rather than branching on compile-time constants scattered through the codebase.

When adding a new environment-dependent value, add it to `AppConfig` — don't invent a parallel
mechanism per feature.

Inspired by the [Compass sample app](https://github.com/flutter/samples/tree/main/compass_app)'s
flavor separation pattern; this is a project decision, not generated by any official Flutter
skill. Rationale: see `docs/adr/ADR-0004-flavors.md`.
